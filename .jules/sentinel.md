## 2024-05-15 - [Missing Input Validation DoS]
**Vulnerability:** Missing input validation in geometry analyzers (`analyzeCircle`, `analyzeLine`, `isVertical`) allowed malformed inputs (`undefined`, `null`, string) to cause unhandled `TypeError` exceptions ("Cannot read properties of undefined (reading 'length')"). This could be easily exploited in a node.js backend context to crash the service, leading to a Denial of Service.
**Learning:** Math utility libraries often assume well-formed array inputs. Even internal libraries need defensive input validation at their boundaries, as upper layers may inadvertently pass unchecked user data down.
**Prevention:** Always validate input types (e.g., `Array.isArray`) at module boundaries and provide a secure, graceful fallback (e.g., returning `{ valid: false }` or throwing custom typed errors) rather than allowing the engine to throw unhandled exceptions.
